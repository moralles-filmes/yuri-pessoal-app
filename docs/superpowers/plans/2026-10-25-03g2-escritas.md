# REDESIGN-03-G2 — as escritas e o fechamento · Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** tornar seguras as escritas do financeiro (erro conferido, atomicidade por RPC, ordem
que erra para o lado seguro), acrescentar a previsão à confirmação de excluir em Lançamentos e
fechar a REDESIGN-03 contra a matriz declarada.

**Architecture:** os valores continuam calculados em TS por funções puras (linha do lançamento,
divisão); duas funções Postgres `security invoker` (`salvar_lancamento`,
`criar_compra_parcelada`) só conferem a forma e gravam numa transação. As sequências que não vão
para RPC (excluir, cancelar parcelas, recorrências, importação) ficam ordenadas com reserva
condicional e frase de `falhaDeEscrita`.

**Tech Stack:** Next.js 16 Server Actions, supabase-js (PostgREST/RPC), PL/pgSQL, Vitest (node,
harness `src/test/supabase-em-memoria.ts`), TypeScript compiler API (varredor).

**Spec:** `docs/superpowers/specs/2026-10-25-03g2-escritas-design.md` — §5 é a forma de cada
item, §5.2 é o SQL **literal**, §6 as mutações.

## Review Focus

1. **Editar só a descrição de uma despesa dividida** — a divisão e os recebíveis não podem ser tocados (`p_divisao` ausente). Teste no Task 3.
2. **Editar transferência que é o pagamento de uma fatura** — o `id` continua o mesmo e a fatura continua apontando para ele. Teste no Task 3.
3. **Dois commits da mesma importação ao mesmo tempo / duas abas gerando recorrência** — cada linha/data entra uma vez. Testes nos Tasks 6 e 7.
4. **Excluir com a leitura da previsão falhando** — o botão fica travado, nada é excluído. Teste no Task 5.
5. **Receita de cartão (estorno) editada** — continua na mesma fatura, sem conta. Teste no Task 3.
