# REDESIGN-03-G — Erro é erro (P0-5) e a fila de riscos de leitura · Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Toda leitura do financeiro (e as do Cron) que falhar ou vier cortada deixa de virar lista vazia / R$ 0,00: lança `ErroDeLeitura`/`LeituraIncompleta`, recusa antes de escrever, ou cai numa tela de erro — sem mudar nenhum número quando a leitura dá certo e sem mover nenhuma escrita.

**Architecture:** Um núcleo puro (`src/lib/supabase/leitura.ts`) com as duas classes de erro e três helpers (`exigir`, `listaComTeto`, `listaCompleta`). As leituras passam por eles; as telas decidem o teto (aviso × erro); as actions capturam só `ErroDeLeitura` e devolvem a frase do momento; o Cron trabalha por família com uma regra pura (`notifications/familias.ts`). Quatro `error.tsx` com um componente compartilhado. Uma varredura AST vira teste e fixa o inventário.

**Tech Stack:** Next.js 16 (App Router, `error.tsx` com `unstable_retry`), Supabase JS (`{data,error,count}`), Vitest (node), TypeScript compiler API (varredor), harness `src/test/supabase-em-memoria.ts`.

**Spec:** `docs/superpowers/specs/2026-10-22-03g-erro-e-erro-design.md` (aprovado em 2026-10-25). O spec é o contrato: textos (§5.3, §5.4, §5.5, D-G19, D-G20, D-G31, D-G33, K1b), a matriz de famílias (§5.8), a tabela de formas (§5.2) e as mutações (§6) são copiados de lá, não reescritos aqui.
